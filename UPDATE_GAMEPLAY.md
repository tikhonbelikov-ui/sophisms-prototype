# Софизмы 2.4 — обновление игры

## Распаковка

- **Уже есть проект 2.4.0.** Распакуйте `Sophisms_Update_2_4_GAMEPLAY.zip` прямо в папку с `package.json` и `App.js`. Подтвердите замену. В архиве лежат `App.js`, `components.js`, `game.js`, `tests/game.test.js` и эта инструкция. Локальные настройки Android и подписи остаются в вашей рабочей папке.
- **Есть только старый проект или клон GitHub 1.1.0.** Используйте `Sophisms_Release_2_4_GAMEPLAY.zip`. Для сборки с нуля распакуйте его в любую папку. Для обновления Git распакуйте полный архив поверх корня клона и подтвердите замену. Если в клоне уже есть свои изменения Gradle или Android, сначала распакуйте полный ZIP отдельно и при переносе сохраните локальную конфигурацию Android, включая ключ подписи. В полном архиве уже есть папка `android`, 63 урока и тесты.

## Проверка и APK на Windows

В PowerShell из корня проекта:

~~~powershell
npm.cmd ci
npm.cmd run test:logic
npm.cmd run check:syntax
~~~

`ci` восстанавливает зависимости по `package-lock.json`. В обновлённой папке 2.4 с уже установленными зависимостями этот шаг можно пропустить. Две команды `run` проверяют игровую логику, учебные материалы и синтаксис JSX.

1. Откройте существующую папку `android` в Android Studio и дождитесь Gradle Sync. Заново генерировать её через Expo не требуется.
2. Если Gradle снова запрашивает Java 25, проверьте **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**. Для вашей прежней конфигурации выберите **JDK 17**. Если в локальном `android/gradle/gradle-daemon-jvm.properties` записано `toolchainVersion=25`, выставьте там `toolchainVersion=17`. Если файла нет, достаточно настройки Gradle JDK.
3. Выберите **Build → Generate Signed App Bundle or APK → APK → app → release**. Используйте тот же ключ и alias, которыми подписан установленный APK. Нажмите **Locate** после сборки, чтобы открыть папку результата.
4. Передайте APK на телефон и установите поверх прежнего приложения. Для обновления должны совпадать пакет `com.sophisms.prototype` и сертификат подписи. Android принимает тот же или более высокий `versionCode`. Полный архив имеет код 7. Если установленный APK имеет код выше 7, установите значение не ниже установленного в `app.json` и `android/app/build.gradle`. Для публикации новой версии через Google Play нужен больший код.

## GitHub

Выполняйте команды из папки репозитория, на ветке `main` с настроенным `origin`. ZIP можно держать вне репозитория.

Если в Git уже есть версия 2.4:

~~~powershell
git add -- App.js components.js game.js tests/game.test.js UPDATE_GAMEPLAY.md
git diff --cached --stat
~~~

Если обновляете старую копию 1.1.0, проверьте `git status --short` перед распаковкой. Из чистого клона после распаковки полного архива:

~~~powershell
git add -A -- .
git diff --cached --stat
~~~

`git add` готовит файлы к коммиту. `-A -- .` включает все изменения из корня клона, поэтому этот вариант подходит после распаковки полного релиза в чистую копию. `--cached --stat` показывает список и объём подготовленных изменений. Проверьте, что там только файлы проекта. Затем:

~~~powershell
git commit -m "Исправить роли и проверку догадок"
git push origin main
~~~

`-m` задаёт сообщение коммита. `git push origin main` отправляет локальную ветку `main` в настроенный удалённый репозиторий.
