# Как собрать подписанный APK «Софизмы 2.4» на Windows

## 1. Распаковать

Распакуйте в отдельную НОВУЮ папку, например C:\Users\igcomp\sp\Sophisms_2_4. Внутри должны находиться package.json, App.js, data и android. Если архив создал дополнительную вложенную папку, корнем проекта считается именно папка с package.json.

Старый проект не удаляйте и не переносите из него папку android поверх новой. Ключ подписи оставьте в надёжном месте.

Это исходники для сборки APK. Все 63 полных урока и 991 вопрос уже внутри; скачивание из GitHub не требуется.

## 2. Инструменты

Нужны:

- Node.js 24 LTS (минимум 22.13).
- Android Studio, совместимая с Gradle/Android Gradle Plugin проекта.
- SDK Platform 36, Build Tools 36.0.0, SDK Platform-Tools и Android SDK Command-line Tools.
- NDK 27.1.12297006, CMake — установите, если их запросит Gradle.
- Gradle JDK 17 или 21; можно выбрать совместимый встроенный JDK Android Studio.

SDK: Tools → SDK Manager. При необходимости включите Show Package Details. Версии взяты из зафиксированных зависимостей React Native 0.86.3. Не выполняйте предложенное Studio автоматическое обновление Gradle/AGP без необходимости.

Проверьте PowerShell:

~~~powershell
node --version
npm.cmd --version
~~~

После установки Node откройте PowerShell заново.

## 3. Зависимости и проверки

В папке с package.json:

~~~powershell
cd C:\Users\igcomp\sp\Sophisms_2_4
npm.cmd ci
npm.cmd run test:logic
npm.cmd run check:syntax
~~~

При ошибке команды исправьте её перед следующим шагом. npm ci использует lock-файл; expo install --fix перед сборкой не требуется.

Интернет нужен при первой установке. node_modules не включена в ZIP: она занимает сотни мегабайт и восстанавливается командой npm ci.

Необязательная предварительная проверка через совместимый Expo Go:

~~~powershell
npx.cmd expo start --clear
~~~

Эта команда не создаёт APK.

## 4. Открыть Android-проект

1. Android Studio → Open → C:\Users\igcomp\sp\Sophisms_2_4\android.
2. Дождитесь Gradle Sync.
3. Установите SDK/NDK, если Studio попросит.
4. При ошибке поиска SDK укажите его в настройках. Обычно это %LOCALAPPDATA%\Android\Sdk.
5. При ошибке Java проверьте Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK: выберите JDK 17/21.

Папка android уже сгенерирована. Для обычной сборки не нужен expo prebuild. Команда expo prebuild --clean пересоздаёт нативные файлы и может удалить последующие настройки.

## 5. Создать подписанный APK

1. Меню Build → Generate Signed App Bundle or APK (может называться Generate Signed Bundle / APK).
2. Выберите APK → Next.
3. Модуль app.
4. Key store path — существующий ключ от установленного приложения.
5. Заполните Key store password, Key alias, Key password.
6. Next → release, выберите папку результата → Create / Finish.
7. После успешной сборки нажмите Locate. Так откроется точная папка результата.

Обычно результаты Gradle лежат в android\app\build\outputs\apk\release, но мастер подписи может использовать выбранную вами папку. Ориентируйтесь на Locate.

Простая команда gradlew assembleRelease без настройки подписи здесь создаёт неподписанный файл. Для установки используйте мастер подписанного APK.

## 6. Ключ подписи и обновление

Ранее у вас встречался файл C:\Users\igcomp\Documents\Sofism_key. Файл без расширения тоже может быть keystore. Но вы также создавали новый ключ, поэтому нужен именно тот, которым подписана установленная сейчас версия.

Не выбирайте android/app/debug.keystore: это стандартный тестовый ключ шаблона, а не ваш релизный ключ. Не создавайте новый ключ для обычного обновления.

Если забыли alias, посмотрите сертификаты в Android Studio либо выполните (пароль будет запрошен отдельно):

~~~powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -list -v -keystore "C:\Users\igcomp\Documents\Sofism_key"
~~~

Если Studio установлена в другом месте, замените её путь. Команда не восстанавливает забытый пароль и не меняет ключ.

Для обновления должны совпадать сертификат и applicationId. В этом проекте пакет com.sophisms.prototype и versionCode 7. Если на телефоне уже код 7 или выше, увеличьте число одновременно в app.json (expo.android.versionCode) и android/app/build.gradle (defaultConfig.versionCode).

Не удаляйте прежнее приложение для обхода ошибки подписи: сначала проверьте ключ. Удаление может стереть локальную партию.

## 7. Установка и проверка

1. Перенесите подписанный APK на телефон и откройте его.
2. Разрешите установку из выбранного источника, если Android запросит.
3. При совпадении пакета/подписи будет предложено обновление.
4. Отключите интернет: проверьте библиотеку, аккордеоны, тесты и набор Энциклопедия · 63.
5. Проверьте игру: правильный ответ +1; первые 20 ошибок расходуют общий банк, следующая ошибка снимает 1 очко. Измените банк в настройках и начните новую партию.
6. Во вкладке «Тесты» проверьте три варианта ответа, завершение, историю и восстановление после закрытия приложения.
7. Проверьте сворачивание, таймер, завершение, клавиатуру и крупный системный шрифт.

Для release APK компьютер и Metro не нужны.

## Как уменьшить размер APK

Тексты уже компактны. Значительную часть размера дают нативные библиотеки и несколько процессорных архитектур. В архиве сохранена универсальная конфигурация.

Если APK нужен только для подтверждённо 64-битного ARM-телефона, можно оставить arm64-v8a в reactNativeArchitectures файла android/gradle.properties. Такой APK не подойдёт другой архитектуре. Без проверки телефона менять это не требуется; удалять тексты ради размера не нужно.

## Что проверено

63 исходника входят в архив, но SOF-005 и SOF-046 редакционно исправлены. Их актуальные SHA-256 приведены в CONTENT_MANIFEST.json. Учебные материалы импортированы с удалением повторных заголовков и приписок о достоверности. Сохранены 991 вопрос и пояснения; исходные ответы приведены к трём категориям с сохранением авторского ключа. Пройдены тесты, JSX, Android/Hermes export; создан Android-проект.

Полная Gradle-сборка и подпись здесь не выполнялись: нет Android SDK и вашего ключа. Установку конкретного APK можно подтвердить только после сборки и проверки на телефоне.
